### C-20260928-4 · 2026-09-28 · 0.3.0: outputs reads the NuGet forms, update-mode retrofits, golden replay for requesting packages, update-mode eval (`nuget-outputs-and-third-run`)
- because: user request (wikiwright 0.3.0 kickoff); the third real run (is-an-image-url 2.0.0 wiki, commit 8861236); the retrofits of the JsonPrettyPrinter (wiki a8c5574) and RandomNameGeneratorLibrary (wiki f0bb65b) wikis to the saved-output rule; T-20260928-4; L-103 to L-114
- files: scripts/wikiwright.py (outputs: input and output pairs, code followed by output, comment values, closing comment runs, the six-word intro window, a command hint; check: heading anchors with inline code); tests/test_wikiwright.py (24 tests); SKILL.md (intro, Step 1, Step 4, Step 5, Step 6, Update mode); references/page-sets.md (fifth wiki, the CLI set tested twice, golden captures with their own fixture server, the command-line-tool sketch marked untested); references/npm.md (proxy CONNECT, Deno without permission, tool versions, typeRoots); references/nuget.md (saved output, snippets from the program, how pages show output); templates/nuget/wiki-verify.template.cs (saved-output note, `Run`, `Possible`, `Captured`); templates/npm/wiki-verify.template.mjs (`chdir`, `run`, a golden-replay section); evals (action-3, update mode, unhinted, with a baseline; evals/grade-action.py); LEARNINGS.md (L-103 to L-105 promoted, L-106 to L-114)
- What changed and why:
  - `outputs` 0.2.0 could not see how the NuGet wikis show output: it checked 6 of JsonPrettyPrinter's blocks (all inputs) and none of RandomNameGeneratorLibrary's 28 values. It now reads an untagged block right after its input or code block, a value in a comment (quoted, JSON-like, a number or literal, after a print call or on a PowerShell expression line, and comment lines closing a block), `# =>`, and a colon-less connective ("becomes"); an intro word counts only within six words of the colon. On the two npm wikis the counts did not drop (33 and 41). A command read as output gets a hint to tag its fence (L-103, L-110).
  - `check` blanked inline code before slugging headings, so an anchor to "## Deno answers `false` for every URL" failed (L-114).
  - Update mode says how to adopt a wiki written before its script was saved, as both NuGet retrofits did: one page sentence was wrong (RandomNameGeneratorLibrary's longest last name), everything else matched once printed (L-104).
  - Step 4 runs other hosts' snippets from the script, prints random examples only after a membership check, replays a golden capture that starts its own fixture server as a child process, and runs the npm script on the oldest Node in `engines` too (L-106, L-111, L-113). Both templates carry the helpers so the next run does not rebuild them.
  - Step 1 runs preflight even when the overlay lists the wiki as owed: one eval run took the record for the state (L-109; flaky, 1 of 5).
  - The page sets record the CLI set as tested twice; applications, monorepos, command-line tools and other hosts stay lacking, with TrailerClipper.Tool named as the candidate for the command-line set.
  - Update mode has an unhinted eval case (action-3) with a baseline, and the action grader lives in the repository (`evals/grade-action.py`), ignoring code when it counts wikilinks and ignoring tool results that only echo the draft.

### C-20260928-3 · 2026-09-28 · 0.2.0: output check, enable-wiki answer, golden captures, update-mode fixes, other hosts (`output-check-and-second-run`)
- because: user request (wikiwright 0.2.0 kickoff); the second run (seeded-random-utilities 2.0.0 wiki, commit 7980d4b); the update-mode rehearsal on get-title-at-url (wiki commit 2807e56); T-20260928-3; R-20260928-2; L-002 (resolved), L-012 (update), L-015, L-017 to L-022
- files: scripts/wikiwright.py (outputs, preflight host detection and elapsed seconds, check --partial, placeholder message); tests/test_wikiwright.py (17 tests); SKILL.md (Step 1, Step 3, Step 4, Step 6, Step 8, Update mode, intro); references/hosts.md (new); references/publishing.md (the four runs, the enable answer); references/page-sets.md (tested kinds table, npm library without a CLI, deterministic output, golden captures); references/npm.md (runtimes from npm, yarn Plug'n'Play, console.log form, time zones); templates/npm/wiki-verify.template.mjs (`example()`, saved output); templates/wiki-note.template.md (saved output, outputs step); evals (action-1 against seeded-random-utilities, new action-2, run-action.sh parameterised by REPO and CASE); LEARNINGS.md (duplicate L-013 renumbered to L-016; L-017 to L-022)
- What changed and why:
  - `wikiwright.py outputs <wiki dir> <verify output>` finds every block a page presents as output (a `text`, `console` or `output` fence, or an untagged or data fence after "Output:", "is:", "gives", "prints" and the like; `$ ` transcripts checked per command; `//=>` values matched as whole lines) and reports each one missing from the verification output, reading the fixture's `http://127.0.0.1:<port>` as `https://example.com`. It makes L-008 and L-009 checkable. On its first real use it found five page outputs on the published get-title-at-url wiki that the saved script never printed in the pages' form (L-019).
  - Update mode now diffs against a saved output. The rehearsal showed the old procedure ("compare with the pages") had no saved output and could not notice hand-converted outputs.
  - Preflight answers the open question: enabling the wiki does not create the repository (61 seconds without it, then 11 seconds after the maintainer's first-page save). It prints elapsed seconds, takes a URL or a clone, and stops with `STATE: other-host` for GitLab, Gitea, Forgejo, Azure DevOps or an unknown host instead of failing inside `gh`. The placeholder line no longer says "force-push allowed" (L-010).
  - Page sets record "npm library without a CLI" and "deterministic or seeded output" as tested, and say how a golden capture feeds Versions and upgrading (replay the capture script against the old and new versions, L-020).
  - `check --partial` for a draft of a few pages (L-015). references/hosts.md from primary docs, marked unverified; applications and monorepos are still listed as lacking.
