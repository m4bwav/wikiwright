# Changelog: wikiwright

Every change to [SKILL.md](SKILL.md) and its companions, newest first, each with the reason. Reasons cite findings in [RESEARCH.md](RESEARCH.md) (`R-`), lessons in [LEARNINGS.md](LEARNINGS.md) (`L-`), and test runs in [TESTS.md](TESTS.md) (`T-`). State in `evergreen.json`. Entry shape: `### C-YYYYMMDD-n · date · one-line summary`, then `because:` (IDs or "user request"), `files:` (file and section), and a sentence on what changed. Cite section headings, not line numbers.

### C-20260929-2 · 2026-09-29 · 0.5.0, step 1: suite driver, cachecheck, releasecheck, the host-fixture kit, the 0.4.1 fixes (`tools-before-suite`)
- because: user request (the 0.5.0 kickoff: token-saving tools before the suite); L-012, L-017, L-116 to L-119
- files: evals/run-suite.sh (new); scripts/wikiwright.py (`cachecheck`, `releasecheck`, `outputs` node markers and `--node`, `diffout` path masks and `--keep-paths`, UTF-8 stdout); tests/test_wikiwright.py (41 tests); templates/npm/host-fixture.mjs (new) and tests/host-fixture.test.mjs (new, run in CI with Node 24); templates/npm/wiki-verify.template.mjs ("by host name" is an import, `OLDEST_NODE` copies the binary alone, `shell()`); SKILL.md (intro, Step 4, Step 6, Update mode step 3); references/page-sets.md (new section "How `wikiwright.py outputs` reads a page", moved from SKILL.md Step 6); references/npm.md (the kit, the oldest Node); AGENTS.md; .github/workflows/tests.yml
- What changed and why:
  - The 0.4.0 session drove its suite by hand and read each grade into its context. `evals/run-suite.sh` runs the action cases one at a time with and without the skill, moves aside any `<target>.wiki` clone a run makes, records the targets' `git status`, prints one line per run and ends with the plugin source's `git status --short`, so eval-written files cannot hide (L-017).
  - A stale plugin cache ran old text twice (L-012); `cachecheck` compares every tracked file under `skills/` and `.claude-plugin/` with the installed copy by SHA-256. On its first use it found three files changed since the 0.4.0 install. `releasecheck X.Y.Z` checks the four version fields, a CHANGELOG entry naming the version, a TESTS run the last tag did not have, and that the tag is free.
  - L-118: `OLDEST_NODE` put the npm `node` package's bin folder first on PATH, which Git Bash skips; it now copies the binary alone into its own folder, and the template's `shell()` prints the Node each shell case ran.
  - L-119: `diffout` crashed on a cp1252 console and saved local paths; it now writes UTF-8 with replacement and masks the new output's folder, the temp folder and the home folder (`<scratch>`, `<temp>`, `<home>`; `--keep-paths` turns it off). `outputs` reads `<!-- outputs: node>=22 -->` and checks such a block only against outputs from those Node lines, so the oldest Node's output can be checked without false misses.
  - The fourth run's script rebuilt the proxy, the CA, the guard, the route preload and the probe inline (about 150 lines of a 48 KB script). They are now one module, `templates/npm/host-fixture.mjs`, that also tests the guard before anything runs (L-117) and refuses to start when Node 20 has no undici; the template imports it.
  - Token measure (before, after): SKILL.md 3,059 words (19,869 bytes), now 2,834 (18,591); the npm template 15,606 bytes, now 12,560 plus a 9,343-byte kit a run reads only for requests by host name, and then only its 2 KB header.

### C-20260929-1 · 2026-09-29 · 0.4.0: diffout, the oldest Node in the template, requests by host name, proxy-recorded captures (`diffout-and-fourth-run`)
- because: user request (wikiwright 0.4.0 kickoff); the fourth real run (markdown-plain-link-replacer 2.0.0 wiki, commit ab33614); T-20260929-1; L-106, L-113, L-115 to L-117; L-007 and L-017 updates
- files: scripts/wikiwright.py (`diffout`); tests/test_wikiwright.py (27 tests, DiffoutTests); SKILL.md (intro, Step 4, Update mode step 3); templates/npm/wiki-verify.template.mjs (`run()` and `cli()` close stdin, the "by host name" section, `OLDEST_NODE`, the golden note, closing every server); templates/wiki-note.template.md (update step 2); references/npm.md (requests by host name, captures recorded through a proxy with TLS, the oldest Node, the CLI's stdin, Deno's `npm:` resolution); references/page-sets.md (the sixth wiki, the CLI set tested a third time, what a host-named fixture needs, lacking kinds as of 0.4.0); README; LEARNINGS.md (L-116, L-117; eval-written L-115 and updates reviewed)
- What changed and why:
  - Update mode's diff was "replace the port and diff by hand". `wikiwright.py diffout OLD NEW` splits two script outputs at their `## label` lines, normalises line endings, trailing spaces and local ports, and prints every changed, added and removed section; `--skip` leaves out sections that print tool versions, `--mask` blanks machine-dependent text, `--save` writes the normalised output to save over the old. On this run it showed the Node 20 output differing from Node 24's in exactly four sections.
  - L-106 depended on memory. The npm template's `OLDEST_NODE=<major>` reruns the whole script under that Node with its folder first on PATH and saves the output beside the main one; SKILL.md Step 4 and the note template name it. First run: Node 20.20.2 and 24.18.0 differed only where Node 20 lacks `NODE_USE_ENV_PROXY`.
  - A package whose requests go through its dependencies to the hosts its input names cannot use the fixture address: its output names the site. The template's new "by host name" section and references/npm.md record what worked: a CONNECT proxy routing by port to a plain and a TLS server, a throwaway CA (Deno refused a self-signed CA certificate as the server's own), `NODE_USE_ENV_PROXY` on Node 24 and undici's `EnvHttpProxyAgent` on Node 20, variables set before each child starts, forward slashes in `NODE_OPTIONS`, a probe to an `.invalid` host (L-116).
  - The socket guard every capture and script used read `args[0].host`, but `net.connect()` passes its arguments as one array, so plain http reached the internet in the first Node 20 run (no page output came from it). The template's guard reads the array (L-117); package-modernize carries the same fix (its L-124).
  - The first replay of a capture that records through its own proxy with TLS needed four patched copies against 2.0.0; references/npm.md and page-sets.md list them, and package-modernize's capture template now makes the first two unnecessary (its C-20260929-1).
  - `run()` and `cli()` close standard input: a CLI that reads stdin without an argument waited for ever.
  - Eval runs wrote L-115 (a `fetch` wrapper that routes by header), updates to L-021, L-106 and L-107, a line in references/npm.md and a stray `package.json`; reviewed: kept, the Deno line narrowed, the `package.json` deleted.

### C-20260928-4 · 2026-09-28 · 0.3.0: outputs reads the NuGet forms, update-mode retrofits, golden replay for requesting packages, update-mode eval (`nuget-outputs-and-third-run`)
- because: user request (wikiwright 0.3.0 kickoff); the third real run (is-an-image-url 2.0.0 wiki, commit 8861236); the retrofits of the JsonPrettyPrinter (wiki a8c5574) and RandomNameGeneratorLibrary (wiki f0bb65b) wikis to the saved-output rule; T-20260928-4; L-103 to L-114
- files: scripts/wikiwright.py (outputs: input and output pairs, code followed by output, comment values, closing comment runs, the six-word intro window, a command hint; check: heading anchors with inline code); tests/test_wikiwright.py (24 tests); SKILL.md (intro, Step 1, Step 4, Step 5, Step 6, Update mode); references/page-sets.md (fifth wiki, the CLI set tested twice, golden captures with their own fixture server, the command-line-tool sketch marked untested); references/npm.md (proxy CONNECT, Deno without permission, tool versions, typeRoots); references/nuget.md (saved output, snippets from the program, how pages show output); templates/nuget/wiki-verify.template.cs (saved-output note, `Run`, `Possible`, `Captured`); templates/npm/wiki-verify.template.mjs (`chdir`, `run`, a golden-replay section); evals (action-3, update mode, unhinted, with a baseline; evals/grade-action.py); LEARNINGS.md (L-103 to L-105 promoted, L-106 to L-114)
- What changed and why:
  - `outputs` 0.2.0 could not see how the NuGet wikis show output: it checked 6 of JsonPrettyPrinter's blocks (all inputs) and none of RandomNameGeneratorLibrary's 28 values. It now reads an untagged block right after its input or code block, a value in a comment (quoted, JSON-like, a number or literal, after a print call or on a PowerShell expression line, and comment lines closing a block), `# =>`, and a colon-less connective ("becomes"); an intro word counts only within six words of the colon. On the two npm wikis the counts did not drop (33 and 41). A command read as output gets a hint to tag its fence (L-103, L-110).
  - `check` blanked inline code before slugging headings, so an anchor to "## Deno answers `false` for every URL" failed (L-114).
  - Update mode says how to adopt a wiki written before its script was saved, as both NuGet retrofits did: one page sentence was wrong (RandomNameGeneratorLibrary's longest last name), everything else matched once printed (L-104).
  - Step 4 runs other hosts' snippets from the script, prints random examples only after a membership check, replays a golden capture that starts its own fixture server as a child process, and runs the npm script on the oldest Node in `engines` too (L-106, L-111, L-113). Both templates carry the helpers so the next run does not rebuild them.
  - Step 1 runs preflight even when the overlay lists the wiki as owed: one eval run took the record for the state (L-109; flaky, 1 of 5).
  - The page sets record the CLI set as tested twice; applications, monorepos, command-line tools and other hosts stay lacking, with TrailerClipper.Tool named as the candidate for the command-line set.
  - Update mode has an unhinted eval case (action-3) with a baseline, and the action grader lives in the repository (`evals/grade-action.py`), ignoring code when it counts wikilinks and ignoring tool results that only echo the draft.

### C-20260928-3 · 2026-09-28 · 0.2.0: output check, enable-wiki answer, golden captures, update-mode fixes, other hosts (`output-check-and-second-run`)
- because: user request (wikiwright 0.2.0 kickoff); the second run (seeded-random-utilities 2.0.0 wiki, commit 7980d4b); the update-mode rehearsal on get-title-at-url (wiki commit 2807e56); T-20260928-3; R-20260928-2; L-002 (resolved), L-012 (update), L-015, L-017 to L-022
- files: scripts/wikiwright.py (outputs, preflight host detection and elapsed seconds, check --partial, placeholder message); tests/test_wikiwright.py (17 tests); SKILL.md (Step 1, Step 3, Step 4, Step 6, Step 8, Update mode, intro); references/hosts.md (new); references/publishing.md (the four runs, the enable answer); references/page-sets.md (tested kinds table, npm library without a CLI, deterministic output, golden captures); references/npm.md (runtimes from npm, yarn Plug'n'Play, console.log form, time zones); templates/npm/wiki-verify.template.mjs (`example()`, saved output); templates/wiki-note.template.md (saved output, outputs step); evals (action-1 against seeded-random-utilities, new action-2, run-action.sh parameterised by REPO and CASE); LEARNINGS.md (duplicate L-013 renumbered to L-016; L-017 to L-022)
- What changed and why:
  - `wikiwright.py outputs <wiki dir> <verify output>` finds every block a page presents as output (a `text`, `console` or `output` fence, or an untagged or data fence after "Output:", "is:", "gives", "prints" and the like; `$ ` transcripts checked per command; `//=>` values matched as whole lines) and reports each one missing from the verification output, reading the fixture's `http://127.0.0.1:<port>` as `https://example.com`. It makes L-008 and L-009 checkable. On its first real use it found five page outputs on the published get-title-at-url wiki that the saved script never printed in the pages' form (L-019).
  - Update mode now diffs against a saved output. The rehearsal showed the old procedure ("compare with the pages") had no saved output and could not notice hand-converted outputs.
  - Preflight answers the open question: enabling the wiki does not create the repository (61 seconds without it, then 11 seconds after the maintainer's first-page save). It prints elapsed seconds, takes a URL or a clone, and stops with `STATE: other-host` for GitLab, Gitea, Forgejo, Azure DevOps or an unknown host instead of failing inside `gh`. The placeholder line no longer says "force-push allowed" (L-010).
  - Page sets record "npm library without a CLI" and "deterministic or seeded output" as tested, and say how a golden capture feeds Versions and upgrading (replay the capture script against the old and new versions, L-020).
  - `check --partial` for a draft of a few pages (L-015). references/hosts.md from primary docs, marked unverified; applications and monorepos are still listed as lacking.
