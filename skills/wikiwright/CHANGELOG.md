# Changelog: wikiwright

Reasons cite findings in [RESEARCH.md](RESEARCH.md) (`R-`), lessons in [LEARNINGS.md](LEARNINGS.md) (`L-`), and test runs in [TESTS.md](TESTS.md) (`T-`). State in `evergreen.json`. Protocol: MAINTENANCE.md.

Entry shape: `### C-YYYYMMDD-n · date · one-line summary`, then `because:` (IDs or "user request"), `files:` (file and section), and a sentence on what changed. Cite section headings, not line numbers.

### C-20260929-7 · 2026-09-29 · 0.6.0, step 1: the file-tree kit, a grader that sees a recorder, a trace digest, two grader fixes (`files-and-grader`)
- because: user request (the 0.6.0 kickoff: a file-writing package, the recorder the grader cannot see); L-122; L-130; T-20260929-3
- files: templates/npm/file-tree.mjs (new) and tests/file-tree.test.mjs (new, 9 tests, in CI); templates/npm/wiki-verify.template.mjs (`cli()` takes `{cwd, env}` as its last argument; the "files on disk" section and `inTree()`); references/npm.md ("Packages that write files"); SKILL.md Step 4; evals/grade-action.py (`FETCH_WRAPPER`, `ROUTES_LOCALLY`, `digest()` and `--digest`, `saved_outputs()`, the wiki-check pattern); tests/test_wikiwright.py (53 tests: the template's files section, the grader); README; AGENTS.md; .github/workflows/tests.yml; LEARNINGS.md (L-130)
- What changed and why:
  - Files on disk. The template had no way to run a case in a scratch tree, and nothing showed a file before and after. `file-tree.mjs` builds a fresh copy of each case's tree, sets fixed modification times, runs the case and prints one line per file (not written, written with the same bytes, changed, created, deleted), then each written file's contents before and after under a header of size, UTF-8, BOM, line endings and final newline, the facts the text hides and `outputs` folds away. The tree's path prints as `<tree>`; read-only files and symbolic links are handled, and unavailable links are listed.
  - The recorder (L-122). A cheap trace signal exists: a file written with a `globalThis.fetch =` wrapper that has no local routing in it (no loopback address, no `*_BASE` variable, no refusal of other origins), then run. The grader now fails that as a request to the real service. Over every stored trace (ww3 to ww7 suites) it flags exactly the T-20260929-2 recorder run the old grader passed, and nothing else.
  - `grade-action.py <run> --digest` prints one line per tool call worth reading (installs, requests with their hosts, node runs, fetch wrappers, git, writes outside the workspace). Reading a trace, which L-122 requires, went from 811 KB to 2.7 KB on the recorder run.
  - Two grader errors found by T-20260929-3: outputs a run saved to files and checked with `outputs` never reached the trace, and preflight through a variable (`python $WW preflight OWNER/REPO`) was not seen as a wiki check. Both fixed and tested; four runs regraded to pass.
- Measured load: the template grew from 13,428 to 14,864 bytes; the kit is 9,938 bytes, of which a run reads the 2,480-byte header, and only for a file-writing package. SKILL.md: 3,028 words before, 3,086 after (Step 4's bullet).
